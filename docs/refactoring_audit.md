# Refactoring Audit And First Batch

Inspected on 2026-10-21 on `refactoring`. This records the first implementation checkpoint, not completion of the app-wide plan.

## Baseline

- The original `yarn lint` passed ESLint, repository rules, and TypeScript without errors.
- Both page/primitives review scripts completed. Their output is advisory: providers, interactive controls, and deliberately styled shells appear alongside genuine extraction candidates.
- Before migration, Stack appeared 169 times across 64 files; Box 12 times across 12 files; Text 175 times across 56 files; Card 44 times across 21 files; Grid once; Icon 32 times across 20 files. These are source-use counts, not rendered instance counts.
- Two component files exported multiple UI components: HeroMetrics/HeroMetric and DetailList/DetailRow.
- Props type aliases were widespread; the previous lint rule accepted both aliases and interfaces.
- Fetch orchestration already lives mainly in protected route sections using authenticated private API handlers. Stateful form components orchestrate mutations and compose shared controls. Preserve these boundaries during further extraction.
- Currency formatting uses `src/lib/utils.ts`; display dates also use date-fns and direct Intl calls across cards, filters, tables, month selectors, and route sections. Date strings used for URL/query/input/scheduling keys are separate from display formatting and must retain their existing semantics.

## Checks And Evidence

- `yarn test:components` covers interface-only props and single-component export rules, typography/semantic preservation, responsive zero/false overrides, and inverse error styling.
- Both new lint standards apply to component/element files. Hook exports and barrels that re-export components remain allowed.
- An AST comparison against the starting revision found 189 Text/Currency uses before and after, including error-view replacements, with no changes to their size, weight, color, or semantic element. This source check complements browser inspection; it is not a complete visual regression suite.
- The login screen's computed typography classes, font size/weight, Stack direction/gap, Box padding, text, and element types matched before/after at 390px and 1440px viewport widths. The email label now correctly associates with its field, and mobile inspection found no horizontal overflow.
- A temporary local fixture verified mobile/tablet/desktop Stack direction/gaps and Box padding, including zero overrides and per-side inheritance. It also verified Input/Select label association, native dialog opening, focus inside the dialog, Escape closing, and focus returning to the trigger. The fixture and its generated route type were removed afterward.
- Full lint/type validation, both advisory review scripts, component tests, and a production build passed at this checkpoint. Re-run them after subsequent runtime changes.
- The local browser session had no authenticated app session. Protected screen visuals, mutations, dark-theme comparison, and additional browser/OS coverage have not been verified. No authentication bypass, production data mutation, or email login was performed.
